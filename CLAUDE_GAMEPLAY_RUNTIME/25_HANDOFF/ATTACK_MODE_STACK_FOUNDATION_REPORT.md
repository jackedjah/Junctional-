## MOVEMENT DRAWER

One drawer element; tapping a mode selects it (host `RULES_SELECT {mode}`) and opens the drawer; another mode replaces its contents; the active mode collapses / reopens it without touching the selection. Entries come only from the authoritative snapshot (`rules.skills[category]`, the equipped slot list): shared movement-pattern name, class-specific resolved attack name (from the presentation profile, e.g. "Titan Drive"), gesture, energy cost and status `SELECTED · READY · COOLDOWN x.x s · LOW ENERGY · UNAVAILABLE IN CURRENT STATE (why)` — all computed by the host (`availability` / `availability_why`). Empty modes show `NO MOVEMENT EQUIPPED`; unassigned exercise mappings are marked "(no exercise mapping yet)". Tapping a pattern arms it only (`RULES_SELECT {slot}`); ATTACK / J / click perform it; hold-for-details is kept and every row has an accessible ⓘ details button; Z cycles modes; 1–4 pick slots. Touch, mouse, keyboard and scripts all call `hud.selectMove()`. The last valid pattern is remembered per class and per mode on the host (`selMemory`), restored on class change and cleared only when no longer legal. Dock listeners stop propagation for wheel / touch / mouse, so scrolling or dragging inside it never reaches lock, camera, movement, dash or attack (measured: camera yaw / zoom, position, casts, energy, cooldowns and lock unchanged before/after). Opening the drawer never clears the four-arrow lock.

## ATTACK-STACK CONTRACT

Recorded in `_runtime_mapping.attack_stacks._doc` and `COMMAND_AUTHORITY_CONTRACT.md`: MOVEMENT PATTERN (`movement_pattern_id`, shared exercise-derived motion) ≠ ATTACK STACK (`attack_stack_id`: class + mode + movement pattern + progression band [+ future specialization]; never an automatic combo / chain / best-move selector) ≠ SKILL REALIZATION (the existing authoritative skill: targeting, startup, commit, effect, cost, cooldown, recovery — untouched) ≠ PRESENTATION PROFILE (`presentation_profile_id`, class-specific treatment). Resolution `RulesMath.resolveStack(frozenRules, {classId, level, category|mode, movement_pattern_id, skill_id, equipped_stack_id})` → `{skill_id, attack_stack_id, attack_stack_revision, presentation_profile_id, progression_band}`; a missing / disabled / band-locked / wrong-class / wrong-mode binding is `ATTACK_STACK_NOT_AVAILABLE` with a deterministic `why` (`NO_BINDING · NO_SUCH_STACK · WRONG_CLASS · WRONG_MODE · WRONG_PATTERN · WRONG_SKILL · NOT_RUNTIME_ENABLED · BAND_LOCKED · NO_PRESENTATION_PROFILE`) — never a fallback into another class or mode. Data migration is additive: 67 bindings generated for the 30 existing skills (their ids, costs, cooldowns, timings, targeting, effects and interruption behaviour are reused verbatim); the 20 special-magic realizations without a verified exercise mapping carry `UNASSIGNED_PATTERN_DEV` and are listed in `attack_stacks.unassigned_pattern_dev` (ATHLETE_VECTOR/TRACK/SET, TITAN_IRON/BRACE, BAGE_MEND/RALLY/VANISH/SHELL/DISCORD/LAST_PULSE/MIST/SEAL, VISIONARY_ANKLE/CHAIN/BARBELL/CABLE, LEAN_BOLT/ECHO/TETHER). `validateStacks` runs at ruleset load and refuses an invalid table.

## LEVEL 1–12 / 13+

`_runtime_mapping.progression_bands` (OWNER-TUNABLE, "12 or so"): `foundation_max_level: 12` stored once; `RulesMath.bandForLevel` / `bandUnlocked` are the only readers (no scattered level-12 checks). Level ≤ 12 = FOUNDATION_PROTOCOL, 13+ = CLASS_DEVELOPMENT (`band_min_level.CLASS_DEVELOPMENT = 13`). Foundation bindings share the protocols across classes but every (class, skill) has its own `attack_stack_id` + `presentation_profile_id`. A CLASS_DEVELOPMENT fixture per class (`AS_<CLASS>_PHYSICAL_HORIZONTAL_PUSH_PA_PUSH_CD_DEVFIX`, same PA_PUSH realization, distinct ids, `fixture: true`) proves band resolution; it is refused at level 12 (`BAND_LOCKED`), is NOT auto-selected at 13 (the foundation entry stays the default equipped entry) and resolves only after an explicit equip (`STACK_EQUIP` dev op). Level comes from the actor's authoritative profile; the `LEVEL_FIXTURE` dev op (journaled PLAY_DEV) sets the band only. The equipped-slot system and the unresolved slot-unlock schedule are untouched; later stack selection / branching stays OPEN.

## FIVE-LINE BABY CONTROL GUIDE

1. Move with W A S D (or the left stick); W always walks toward the top of the screen. Drag to look around.
2. Click or tap an enemy to lock on (four arrows). Esc or the LOCK button clears it.
3. Top-right: pick PHYSICAL, PHYS MAHGIC or SPECIAL MAHGIC, then tap a move in the drawer (tapping never attacks; hold or ⓘ shows details).
4. Press J, click the ground or the ATTACK button to perform the selected move. Free roam is harmless; PRACTICE BATTLE turns damage on for the dummy.
5. FLY [F] takes off (Space up, C down, F lands). No flight in a MAH MATCH. F3 shows developer info.
