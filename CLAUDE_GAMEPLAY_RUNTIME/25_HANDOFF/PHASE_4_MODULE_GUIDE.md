# GAMEPLAY RUNTIME PHASE 4 — MODULE GUIDE (persistence · input · interaction · world shell · QA tools)

Everything below is DEVELOPMENT quality. No Blender, no Astra assets, no final art / VFX / animation, no networking, no commerce. Every number comes from `00_CORE/dev_tuning.dev.json` (EXPERIMENTAL) or the canonical `PLAYER_MOVEMENT_DEFAULTS.json`; the new modules hold none.

| folder | module | what it owns | what it deliberately does NOT do |
|---|---|---|---|
| `18_PERSISTENCE` | `PlayerProfileStore.js` | versioned persisted profile (`schema_version` **1.0.0** from `persistence.schema_version`), `newProfile / save / load / validate / migrate / resetDevelopment`, `fromGameplay` (captures level, xp, permanent stats, mentor + activity progress, cosmetics identity, unlocks, last_world / last_spawn) and `applyToGameplay`; storage adapters `createMemoryStorage` (tests), `createFileStorage(fs, path, dir)` (node), browser `localStorage` wrapper lives in the sandbox | no accounts, no backend, no cloud; **temporary buffs are refused by `validate`** (`temporary_buffs` / `active_buffs` / `buffs` keys fail); unknown / newer schema versions are refused, never guessed |
| `19_INPUT` | `InputRouter.js` | one canonical intent list (MOVE, LOOK, INTERACT, TRANSFORM, FLIGHT, ASCEND, DESCEND, MOVEMENT_PATTERN_SELECTION, ATTACK_DIRECTION, ATTACK_PRIMARY, ATTACK_SECONDARY, EMOTE, MENU); adapters KEYBOARD_MOUSE (dev default), CONTROLLER (PLACEHOLDER_LAYOUT, OD-28), TOUCH_FUTURE (INTERFACE_STUB, OD-13 / OD-24); `remap` for configurable mappings; intents → the authoritative `InputActions` (`06_INPUT`) which gained LOOK / MENU / ENTER_FLIGHT / EXIT_FLIGHT | no gameplay logic (test-asserted: no health / damage / xp / ceiling words); adapters never call systems |
| `19_INPUT` | `FlightControls.js` | ENTER_FLIGHT / EXIT_FLIGHT / ASCEND / DESCEND / FORWARD / BACKWARD / STRAFE over the **existing** `FlightSession` + `MovementCapabilities`; combat context is read from the flight session mode | no ceilings, no drain, no new flight rules |
| `20_INTERACTIONS` | `InteractionSystem.js` | interaction points `{interaction_id, type, position, range_m, requirements, available_actions, prompt, session_handler}`; 11 types; range detection per tick; device-neutral prompt `{label, intent:'INTERACT', glyph_slot:'CONFIRM', eligible, blocked_by}`; eligibility from data (form, min_level, unlocks, quest_completed, not_in_combat, grounded); `interact()` confirms the nearest eligible point; `createDoorTransition` (IDLE → APPROACH → AVAILABLE → CONFIRMED → TRANSITION → ENTERED → EXITING) with injectable `loadingStrategy` (OD-25) and `transitionStyle` (OD-26); `standardHandlers` bind types to runtime systems (climb → `createClimbingHooks`, mentor / duel / activity / raid via injected objects or functions) | no interiors, no platform icons, SWIM returns OD-09, TRANSPORT returns a placeholder tagged OD-27 |
| `21_WORLD_SCHEMA` | `WorldRegistry.js` + `data/worlds.dev.json` | data-driven world definition (world_id, name, environment / architecture / nature / transport profiles, shared_infrastructure, activity_locations, mentor_locations, wild_monster_set, ultimate_boss, raid_zones, spawn_points, pois); POI registry types GYM, DUEL_ARENA, MENTOR, ACTIVITY, TRANSPORT, RAID, SHOP_FUTURE, SOCIAL_SPACE, BUILDING_INTERIOR, WORLD_EXIT; `poiToInteraction` derives interaction points (climb POIs require SPLIT + grounded); validation refuses unknown infrastructure, missing default spawn, exits to unknown worlds and **any defined monsters** | no maps, no art, no commerce, no monsters, no bosses |
| `22_DEBUG_BOT` | `DuelBot.js` | seeded (mulberry32) deterministic opponent: IDLE / MOVE / DEFEND / ATTACK / RANGED / DEFEATED; contact basic + upright-row ranged fixture through the existing `createAttackExecution`; `incoming()` applies the defend reduction; all numbers under `dev.bot` | not production AI, no pathfinding, no targeting policy (OD-15) |
| `23_REPLAY` | `SessionRecorder.js` | `createSessionRecorder` (inputs from INPUT_ACTION, gameplay / mahloco / flight / resource / attack / duel / interaction / XP events, periodic state samples, `duration_s`), `replaySession` (re-issues inputs into a fresh world for exactly the recorded duration), `compareRecords` (mahloco state, form, pattern, flight per sample + ordered key event sequence; divergences are reported, never hidden) | positions are not replayed (no kinematic controller in the headless runtime); the sandbox replays into the live world and says so |
| `24_TEST_SCENARIOS` | `scenarioHarness.js`, `scenarios.js`, `run_scenarios.mjs` | one harness composing the Phase 2 world with every Phase 4 system the way the sandbox does; SCENARIO_01 … 07 as listed in the brief; `node 24_TEST_SCENARIOS/run_scenarios.mjs [ID] [--json out]` | scenario positions are logical (teleport), physics is not simulated |
| `16_TESTS` | `gameplay_phase4.test.mjs` | 85 checks covering persistence, migration, input abstraction, interaction range / eligibility, door contract, flight controls, world / POI registry, deterministic bot, record / replay, all seven scenarios, boundaries | — |
